### P2 survey: anomaly / intrusion detection for Kerberos attacks (STATUS: PARTIAL, about 20 external-source calls used)

Scope note: thin literature. Searched arXiv-by-ID, Splunk/Kerberos industry material, Google Patents, LANL dataset page and four web searches; found 4 works fully read (2 are the same authors), 1 patent partially read, and 6 leads that were NOT opened. Not exhaustive; see QUERIES RUN and NOT ACCESSIBLE / UNVERIFIED.

Novelty flags (design: async scorer on KDC logs -> per-principal risk table; KDC policy plugin shortening lifetime/renewal or veto/step-up; signed hash-chained KDC audit log):
- Detector that FEEDS BACK into ticket issuance: NONE found in the works actually read. Every read work is alert/detect-only. Closest threat: Qomplx patent family claims "detection and mitigation"; US12580898 was read later (see UPDATE note at the end): mitigation = post-hoc ticket destruction on domain-controller agents, not adaptive issuance. Other family members remain unread. One web search for "risk-adaptive Kerberos KDC ticket lifetime" returned no academic work (search-engine summary, snippets only).
- Ticket lifetime appears only as a detection FEATURE (Grippo & Kholidy, proposed not evaluated; MITRE DET0144 snippet), never as an enforcement output.
- Hash-chained / signed KDC audit log: nothing found in P2 searches. Qomplx patent uses "hash values" on graph edges as per-transaction identifiers for a passive-capture ledger; it is not a signed tamper-evident KDC log. Qomplx 12580898 ("Master ledger ... forged authentication attacks") was read afterwards (2026-11-22; see UPDATE note at the end): one hash per authentication object, not a hash chain, no signature.
- Per-principal statistical baselining on KDC events exists in industry (Splunk 3-sigma per-host rule on 4769 counts) and academically per source-user (Kotlaba 2021 features), so the "scorer" idea alone is not novel; the issuance coupling and the audit log are where no prior art was found.
